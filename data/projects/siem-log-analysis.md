# SIEM Log Analysis

## Project Type
Security Operations / SIEM / Log Analysis portfolio project.

## Overview
This project focuses on understanding how security logs can be collected, searched, filtered and analyzed to identify potentially suspicious activity.

The project demonstrates the role of log analysis in a SOC environment and how security telemetry can support investigation and incident detection.

## Objective

The main objectives are:

- Understand SIEM concepts
- Analyze security logs
- Identify relevant events
- Filter large amounts of security data
- Recognize suspicious patterns
- Correlate related events
- Build an investigation mindset
- Understand how SOC analysts use centralized security telemetry

## What is SIEM?

SIEM stands for Security Information and Event Management.

A SIEM platform can help security teams collect and analyze logs and security events from different sources.

Examples of telemetry sources can include:

- Windows Event Logs
- Linux logs
- Authentication events
- Network devices
- Security tools
- Applications
- Endpoint security systems

## Log Analysis

Important information that can be examined in security logs includes:

- Timestamp
- Source
- Destination
- Username
- Hostname
- Event type
- Event ID
- IP address
- Port
- Process
- Authentication result
- Severity
- Event frequency

## Investigation Workflow

A typical SIEM investigation can follow this process:

1. Identify an interesting or suspicious event.
2. Review the event details.
3. Determine when the event occurred.
4. Identify the affected user or host.
5. Examine source and destination information.
6. Search for related events.
7. Build a timeline.
8. Look for repeated or unusual behavior.
9. Correlate multiple events when possible.
10. Determine whether the activity requires further investigation.
11. Document the findings.

## Examples of Suspicious Patterns

Potentially interesting patterns can include:

- Multiple failed login attempts
- Successful login after repeated failures
- Login from an unusual location
- Unexpected administrative activity
- Repeated authentication failures
- Suspicious process execution
- Unusual network connections
- Unexpected privilege changes
- Abnormal event frequency

These patterns are indicators for investigation and should not automatically be treated as confirmed malicious activity.

## SOC Relevance

Security analysts can use centralized logs to:

- Monitor environments
- Investigate alerts
- Detect suspicious behavior
- Correlate events
- Build incident timelines
- Support incident response
- Search historical activity
